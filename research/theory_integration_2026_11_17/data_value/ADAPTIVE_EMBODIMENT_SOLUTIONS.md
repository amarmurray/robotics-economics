# Instructor solutions — embodiment/data option exercises (separate)

1. Posterior matching probability after a correctly labeled report is alpha. Only R earns 2. With EA and R, report A selects EA at expected 4alpha and report B selects R at 2, giving 1+2alpha. With EA,EB and R, either report chooses its matching policy, giving 4alpha. Incremental enabling EB is 2alpha-1. At alpha=1/2 it is zero: source technical availability alone is not current gross economic value.
2. E0 guarantees 7/2; both specialists with the report earn 4alpha. Thus full-menu gross=max(7/2,4alpha). At alpha<=7/8 E0 is already optimal and extra paired source plus report is gross-irrelevant in this one window. Access can remain harmless if the old menu and no-cost nonuse are feasible, and later J may differ.
3. Old EA/EB menu has no-report 2, perfect-report 4: VOI=2. Adding E0 makes no-report 7/2 and perfect-report 4: VOI=1/2, cross difference -3/2. In contrast adding EA/EB to old R raises VOI 0 to 2. These are normalized buyer-production contributions assuming every listed whole policy is certified and selectable after reporting.
4. An early hardware lock means the postreport action menu has R and only one specialist: optimum 1+2alpha. If no R remains physically feasible and specialist identity is locked before Y, both choices earn prior 2 irrespective of the later signal, so VOI=0. Validate the full physical retry/reconfiguration path, report arrival, operator coverage and original customer SLA before treating a fallback as feasible.
5. Pre-register held-out original tasks with joint qualification, source mixture/paired grounding factorial, training rights/compute matching, original buyer offers/refusals/receipts, operator use, four whole approved policy menus and randomized report availability/timing. Isolated success marginals conceal dependence and capacity; selected C responses need denominator and independent cross-menu transport. Never infer signed physical safety or dollars from benchmark performance.
