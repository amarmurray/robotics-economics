# Proof ledger — robust original-service recovery and qualification

**20 November 2026.** Established finite-state safety-game mathematics with a conditional robotics production interpretation, **not** independently novel theory, measured robot performance, or an actual approval.

**P1: finite-horizon exactness.** Assume all legally/physically permitted old-controller actions at every state and all feasible disturbance successor states appear in a finite graph; the goal G is absorbing and safe; actions take one modeled time step; the full Markov state records remaining clocks, shared operator access and rights. Define W0=G and Wt as in [main chapter](ROBUST_RECOVERY_GAME_AND_DATA_VALUE.md). For t=0, service is guaranteed exactly in G. Suppose W(t-1) is the set with a guaranteed old-controller policy in t-1 steps. From a non-goal safe state, a guarantee in t steps requires an action for which **all** disturbance successors lie in W(t-1). Conversely such an action, followed by guaranteed continuation, succeeds. This proves necessity/sufficiency by induction. If the state is unsafe, or legal action set empty, there is no qualifying strategy. A state already in W(t-1) remains winnable; this justifies the union.

**P2: exact preaction admission for a fixed X action.** Let t>=1. Define the nonempty successor set of X by all possible next states, including unsafe faults, an incomplete irreversible item, lost operator availability and missed deadlines. After X's first step, only the actually permissible old-controller actions remain. Every successor in W(t-1) is **sufficient** by P1, and the trajectories are safe if W is a subset of K. If even one possible successor is outside W(t-1), the environment can select it, and no old-only recovery can guarantee completion within the remaining horizon. Hence the subset condition is also necessary *for the asserted worst-case model and this action class*. An alternative body or training action may enlarge the allowed recovery class, but must be explicit.

**P3: original robust physical retention.** If the original state s lies in Wt, the original R fallback guarantees complete physical qualification. The new selector executes X only when the exact P2 subset test passes, otherwise chooses the old winning strategy. Thus the resulting controller guarantees physical qualification from any original state in Wt. This is a robust-set inclusion, not a pointwise potential-outcome guarantee of X or a theorem about customer spending. Outside Wt, R may happen to succeed on realized disturbances; P3 does not preserve every such realization. The selector must itself have valid state observation, operating permission and rights.

**P4: disturbance and resource monotonicity.** If each old action's successor support increases, K,G, permitted actions and horizon remain identical, induction shows Wnew_t is contained in Wold_t. The inclusion may be strict: one additional successor can break a universal guarantee. A genuinely admissible independent redundant recovery action may expand W by enlarging the existential action set; it can fail to do so if the same operator is needed. Source data changing only mean empirical success rates cannot change the mathematical certificate until support or model premises change.

**P5: economic limitation.** In Model A, an admitted recipe only enlarges a *physically feasible set* where current buyer menus/rights and operator resources are held fixed; customer maximization is over paid, qualified complete service, not the number of winning states. In Model B, the Bellman continuation already includes data-induced learning; any second added data premium is double-counting. No general sign on X/G/E net value follows from admission alone, because new prices, captured receipts, certification cost, displaced labor, training expense, and delayed demand are not covered by P1–P4. Free optional data preserving the old feasible action set cannot decrease optimized gross value by set inclusion; forced training does not satisfy that premise.

**P6: finite exact demonstrator and independent check.** The exact JavaScript source constructs W0=\{done\}, W1=W2=\{done,initial,retry\}. Because the X action must consume one step, only outcome sets fully contained in \{done,initial,retry\} can pass in general, but in the example candidate outcomes intentionally exclude \`initial\`; therefore exactly 3 of 31 nonempty candidate subsets pass: \{done\}, \{retry\}, \{done,retry\}. The code checks the explicit operator, deadline and unsafe-fault failure cases, monotonicity with more time, and a tighter safe set. Forty-seven assertions passed; separate Python combinations/sets reproduced all three admitted subsets. Neither finite computation proves the inductive theorem nor validates a robot's disturbance set.

**Remaining identification gap:** the support set for actual X action and the complete post-X recovery graph, including rare unsafe tails and operator/buyer interference, are unavailable. This method proposes how an independently certified abstraction *could* support the physical premise of the earlier sequential fallback. Formal safety verification for a real product is outside this research authorization.
