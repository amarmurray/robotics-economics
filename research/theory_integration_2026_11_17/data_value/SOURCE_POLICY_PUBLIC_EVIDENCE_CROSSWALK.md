# Public technical source evidence versus original-buyer policy value — prospective and unpopulated

**20 November 2026.** Primary public routes inspected for the November 22 Models A/B gate; no actual dataset downloaded, policy trained, robot operated or customer panel accessed. This is the evidence companion to [the sequential source-policy derivation](SOURCE_POLICY_SEQUENTIAL_IDENTIFICATION.md).

## Verified source routes (public documentation, not local dataset execution)

**DROID official project** — https://droid-dataset.github.io/droid/the-droid-dataset (read 20 Nov 2026). Its documented RLDS schema includes language instructions, action, joint/gripper observation, terminal flags, reward and file provenance. The project page supplies a full RLDS Google Cloud route, reported as 1.7 TB, and a small 100-episode debug route, reported as 2 GB; neither was downloaded or independently size-tested. Raw data documentation describes trajectory/recording and collection metadata. Its official policy-learning repository (https://github.com/droid-dataset/droid_policy_learning) documents co-training alongside target demonstrations. Demonstration terminal rewards are **not original customer paid receipts**. This documentation does not establish a longitudinal pre-source randomized policy trial, shared commercial operator network, signed whole-policy qualification, natural buyer offer/refusal census or paid invoice records.

**Open X-Embodiment official repository/project** — https://github.com/google-deepmind/open_x_embodiment and https://robotics-transformer-x.github.io/ (read 20 Nov 2026). The project describes pooled RLDS robot episodes, reported 1M+ trajectories across 22 robot embodiments, and RT-X technical transfer evaluations. These are publisher claims at the inspected project layer, not this research's verification of each constituent dataset. The repository points to constituent metadata and individual citations; **check each upstream dataset's license, provenance and hardware/action compatibility** before a data-use proposal. Cross-embodiment benchmark gains do not establish a customer's paid production response or a deployable physical safety certificate.

## Minimal original-network prospective schema

Create immutable original network_id, calendar cohort, baseline original-order census and offered contract version. Before development: source-program assignment, its propensity, source-lineage subtypes, rights, acquisition/compute/curation costs, inherited robot and safe R baseline. After development: *paired* Q_A/Q_B and signed certification/compatible embodiment hashes; target report Y and independently ascertained T where lawfully available, timing and selection/missingness; body lead/lock; before-action operator state and admissible action set with logged propensity. After assignment: requests/accepted/refused/unserved, qualified deliveries, actual paid receipts, invoiced-but-unpaid flags, refunds, downtime, displaced old customer service, recovery and humans, full signed version identifiers. Never recode missing payments as zero or equate invoice face value to cash.

The scientific **stop rule** is explicit. Missing physical signoff means no live new-policy exposure. Missing policy assignment support means mechanism bounds or new separately approved design, not extrapolated IPW; zero propensity cannot be weighted. Missing original-market receipt panel means only technical/physical outcomes can be claimed. Shared controller updates or dispatch interference across nominal clusters require a closed larger network or a supported exposure mapping.

This audit improves identification *feasibility*, but the November 22 scientific gate remains **OPEN**. DROID/OXE can seed future authorized matched technical comparisons; neither public release is the missing customer/robot/operator production backbone. The official BEA quantitative interindustry flow remains unverified, and an unrelated vendor launch is not a substitute.
